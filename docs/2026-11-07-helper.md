# Helper 2.0 (`sdk/sys/core/helper.js`)

`helper.js` es la capa de utilidades de la ruta heredada de Webix. Publica el
global `__` y lo consumen `sdk/app`, `sdk/sys/plugins`, `sdk/sys/widget` y
`sdk/sys/core/session.js`. No se carga en la ruta nueva (`source.json`): ahi el
papel lo cumplen `sdk/compat/globals.js` y `sdk/compat/session-shim.js`.

## Que resuelve

- URL de la API con query codificada y cache-busting (`req`).
- Transporte HTTP con Webix o, si no esta, XHR nativo (`GET`, `POST`, `PUT`,
  `PAYLOAD`, `request`).
- Storage local y de sesion con fallback (Webix -> localStorage/sessionStorage
  -> memoria).
- Cookies, titulo, routing por hash, entorno de dispositivo.
- Formularios Webix (`getFormPost`) y helpers de vistas (`dataFill`,
  `comboFill`).
- Punto de extension para integraciones (`__.registerIntegration`). Las
  integraciones concretas (`databot`, `firebase`) viven en
  `sdk/sys/integrations/` y son opt-in; el nucleo no las carga.

## Contrato

| Metodo | Resultado |
| --- | --- |
| `__.req(object[, options])` | URL con query codificada; agrega `rid` salvo `{rid:false}` o `__.cacheBust=false`. |
| `__.GET(object, cb[, onError])` | `cb` recibe el JSON parseado. Si no es JSON y no hay `onError`, recibe `{error:"Content non json format"}`. |
| `__.POST(object, body, cb[, onError])` | `cb` recibe el JSON parseado. |
| `__.PUT(object, body, cb[, onError])` | Igual que `POST`. |
| `__.PAYLOAD(object, body, cb[, onError])` | `cb` recibe el **texto crudo** (compatibilidad con `SQL*`). |
| `__.request(method, url, body, cb[, onError][, options])` | Punto unico; `options.json`, `options.raw`, `options.timeout`. |
| `__.sendPost(object, body, viewback[, onError])` | Muestra mensaje, navega con `app.require(viewback)` solo si el backend no devolvio error. |
| `__.storage.set/get/remove` | Local. `__.storage.session.*` para sesion. |
| `__.get_user()` | Sesion guardada por el login heredado, o `false`. |
| `__.setCookie(name, value, days[, options])` | `SameSite=Lax` por omision; `Secure` en HTTPS. |
| `__.changeUri(module)` | `history.pushState('#!...')` con fallback a hash; emite `route`. |
| `__.on/off/emit` | Eventos internos (`route`). |
| `__.environment()` | `width`, `height`, `dpr`, `isTouch`, `isMobile`, `isDesktop`, `isIOS`, `breakpoint`. |

## Decisiones del refactor

### Transporte unico

Antes cada metodo repetia la llamada a Webix y el parseo. Ahora todos pasan por
`request`, que:

1. usa `webix.ajax()` si existe (conserva cookies, headers y errores de Webix);
2. si no existe, usa `XMLHttpRequest` con `application/x-www-form-urlencoded`
   para formularios y `application/json` para `PAYLOAD`;
3. parsea con `JSON.parse` y nunca con `eval`;
4. distingue `GET` (JSON parseado) de `PAYLOAD` (texto crudo), que es lo que
   espera el codigo heredado.

`GET` conserva el contrato de error como objeto (`{error:...}`) cuando no se
pasa `onError`; con `onError` entrega un `Error`.

### `req` y cache

`req` sigue agregando `rid=<timestamp>` para evitar cache, pero ahora:

- codifica claves y valores con `encodeURIComponent`;
- respeta una base que ya trae query (`/api?x=1` -> `/api?x=1&...`);
- funciona con base vacia (`?action=...`) como en `make legacy`;
- se puede apagar con `{ rid: false }` o `__.cacheBust = false`.

### `sendPost`

La version anterior hacia `eval`, mostraba `type:"error"` con el texto
"actualizado correctamente" y navegaba siempre. Ahora:

- no evalua texto;
- solo navega si la respuesta no trae `error`, `ok:false` o `status:false`;
- muestra `success` en exito y `error` en fallo;
- acepta `onError` opcional.

### Storage y sesion

`storage` usa Webix si esta; si no, `localStorage` con JSON; si el navegador
bloquea storage, memoria. `storage.session` y `storage.local` quedan expuestos.
`get_user()` lee `usr.session.key` y tolera que falte la configuracion.

### Dispositivo

`mobileAndTabletcheck()` dejo de usar el regex gigante de user-agent. Usa
`__loader.environment()` si existe; si no, `pointer: coarse`/`maxTouchPoints`/
`ontouchstart`. `environment()` expone breakpoints (`sm`/`md`/`lg`).

## Integraciones

`helper.js` no conoce Firebase ni `databot`. Solo expone el registro:

```js
__.registerIntegration('nombre', implementacion); // publica __.integrations.nombre
__.getIntegration('nombre');
```

Las integraciones se cargan aparte, desde el manifiesto o en runtime:

```js
__loader.loadScript('sys/integrations/firebase.js');
```

- `sdk/sys/integrations/firebase.js`: publica `__.firebase` y
  `__.integrations.firebase`. Requiere que la aplicacion configure
  `__.current.FIREBASE`.
- `sdk/sys/integrations/databot.js`: publica `__.integrations.databot` y
  conserva los alias historicos `SQLCombo`, `SQLTable`, `query`, `query_combo` y
  `query_list`. `source-legacy.json` lo carga para no romper la ruta heredada;
  `source.json` no carga ninguna integracion.

Deprecado: `databot` envia `{"action":"databot"}` con SQL desde el cliente. Es
un riesgo de seguridad y un acoplamiento fuerte al backend; no deberia usarse en
codigo nuevo. `addslashes` tampoco es un control de seguridad.

## Que sigue

La recomendacion es descomponer `__` en modulos explicitos antes de retirar
Webix:

- `sdk/src/core/http.js` (fetch + AbortController + errores tipados);
- `sdk/src/core/storage.js` (local/session con namespacing y TTL);
- `sdk/src/core/env.js` (viewport, touch, tema, reduced motion);
- `sdk/src/core/url.js` (base de API, query, rutas);
- `sdk/src/core/form.js` (serializacion y validacion).

`__` queda como fachada de compatibilidad para las pantallas heredadas. El
codigo nuevo importa los modulos; no lee ni escribe `window.__`.

## Verificacion

- `node --test test/helper.test.js` (19 tests, Webix/DOM falsos en `node:vm`,
  incluye carga de integraciones).
- Suite completa: `npm test` (54 tests).
- Firefox real: la ruta heredada (`source-legacy.json`) carga helper 2.0 y
  `databot`; `firebase` queda en `undefined` hasta que se carga su archivo.
  `__.GET` devuelve JSON parseado, `__.POST` envia form-urlencoded y devuelve
  JSON, y `__.PAYLOAD` envia `application/json` y entrega el texto crudo. La
  misma API sin Webix funciona por XHR nativo. Un probe con
  `helper + firebase + databot` registra ambas integraciones y `__.firebase.add`
  publica contra `current.FIREBASE`.
